Базовий компонент

Поле форми

Підпис, поле вводу й кастомний select одного тону — без рамки, лише зсув паперу відрізняє поле від фону.

.field.field > label.cap.fsel

Анатомія

Три поля одного `.field`-блоку: текстовий інпут, textarea й окремий `.fsel` — кастомний select.

  1. Підпис(.field > label / .cap) — 11px, uppercase, --text-muted: називає поле, не декорує його.
  2. Поверхня полятло --bg-surface (paper-2, світліше за канвас), без рамки, радіус 12px, висота 48px для інпуту й select — той самий механізм глибини, що й у карток.
  3. Textareaта сама поверхня, мінімальна висота 96px, вертикальний resize.
  4. Кастомний select(.fsel) — нативна стрілка прибрана через appearance:none, замінена CSS-стрілкою ::after.

Кастомний select (.fsel)

Коли вживати

.field — стандартна обгортка для будь-якого текстового введення в системі: від входу й верифікації телефону/коду до створення оголошення кімнати, скарги, звернення в підтримку й редагування профілю. .fsel — окремий кастомний select для випадних списків, зараз використовується у фільтрі каталогу (listings). Обидва компоненти читають той самий візуальний закон полів: тло --paper-2, без рамки, радіус 12px. До 2026-07-24 .fsel лишався єдиним винятком зі своєю рамкою, скопійованою зі старого чернетки listings.html — рамку прибрали, і тепер усі варіанти поля виглядають однаково.

login / verify-phone / verify-code room-create report / support profile-create-* *-edit listings-desktop — фільтр (.fsel)

Правило і антиправило

Так

Жодне поле — ні інпут, ні textarea, ні .fsel — не має рамки. Глибина сигналізується лише зсувом тону --paper-2 над канвасом, так само, як у картки.

✕ Ні

Повертати рамку .fsel, «бо це список і має виглядати клікабельним». DESIGN.md фіксує саме цю спробу 2026-07-24 і скасовує її: .fsel був єдиним винятком, скопійованим зі старого чернетки — «той самий компонент має виглядати однаково всюди».
