Базовий компонент

Рядок списку

Одна структура «медіа + тіло + бічна колонка» під усі списки застосунку — діалоги, кандидати, оголошення господаря, учасники розмови.

.list.row.row-title.row-meta.row-side.row-unread.row-actions.person-row

Анатомія

Рядок діалогу з непрочитаним повідомленням, у складі списку з роздільником.

  • фото Олена Кімната на Подолі Можемо созвонитись і домовитись про перегляд? 2 год тому1
  1. Медіа-слотаватар чи мініатюра зліва — власна сторінка «Аватар».
  2. Тіло(.row-body) — .row-title (вага 700) над .row-meta (муted, до двох рядків: контекст і прев'ю).
  3. Бічна колонка(.row-side) — час зверху, .row-unread знизу: кобальтова піґулка-лічильник, той самий голос дії, що й ціна.
  4. Роздільникживе на <li>, не на .row — навмисне рішення, див. антиправило нижче.

Варіанти й розміри

Один клас .row під п'ять різних екранів; окрема родина .person-row для компактного «людина в один рядок».

Коли вживати

.row усередині .list — стандарт для будь-якого вертикального переліку з медіа-слотом: список діалогів (dialogs, з прев'ю й лічильником непрочитаних), вхідні заявки (candidates, з бейджем і парою дій «Прийняти/Відхилити»), оголошення господаря (my-listings, зі статус-піґулкою), заблоковані (blocked, з дією «Розблокувати»). У станах завантаження ряд заміщується скелетоном, у порожньому стані список не рендериться — показується порожній стан. Окрема, свідомо простіша родина .person-row — для контексту, де людина показується компактно в один рядок без прев'ю й дій: співрозмовник у шапці chat, господар у картці room.

dialogs — непрочитані, прев'ю candidates — бейдж + дії my-listings — статус-піґулка blocked — «Розблокувати» chat, room — person-row

Правило і антиправило

Так
.list > li { border-bottom }

Роздільник ставиться на <li>. Коли рядок має власні дії знизу (.row-actions, наприклад «Відкликати заявку»), лінія все одно лягає точно під усім вмістом свого запису.

✕ Ні
.row { border-bottom }

Ставити рамку прямо на .row. Коментар у list.css фіксує саме цей баг: коли роздільник жив на .row, кнопка дії опинялась під лінією й візуально прилипала до початку наступного запису замість власного (аудит 2026-07-29).
