# One-shot prompt — RJ5 «відгук після спільного проживання»

```text
Ти працюєш у репозиторії «Куток». Зроби ізольований статичний frontend-приклад нового job
RJ5 «Підтвердити свою надійність для наступного разу» тільки в `examples/one-shot/`.
Не змінюй жодного файла поза цією текою і не вводь нових глобальних токенів або компонентів.

Перед реалізацією послідовно прочитай і застосуй:

1. Product/job: `research/jtbd.md` → RJ5; `sitemap.md` → сутність «Відгук», група F і рішення
   безпеки #6. Зафіксуй як припущення, а не доведений контракт: добровільне підтвердження
   заселення, 14-денне вікно і одночасна двостороння публікація мають `[?]`; RJ5 post-MVP.
2. Voice: `voice.md`. Пиши українською на «ти», спокійно й конкретно; факт перед епітетом,
   без urgency, вигуків, емодзі, AI-кліше, мотиваційного тону й слова «успішно».
3. Microcopy: `wireframes/microcopy.md`. Використай наявний словник системних дій і патерни
   empty/loading/error/success; не займай користувацький контент. Для нового тексту дотримуйся
   `voice.md`, а не наслідуй зафіксований у старих екранах дрейф «ти/ви».
4. Components/patterns: `ui/inventory.md`, `ui/shell.html`, `design-system/README.md` і
   `design-system/components/`. Перевикористай `.app`, flow-shell, header/tabbar, `.section`,
   `.field`, `.btn`, `.banner`, `.state-block`, skeleton і `.review`. Нові класи дозволені лише
   локально в `examples/one-shot/styles.css` для композиції цього прикладу; не копіюй глобальний
   component CSS.
5. Tokens/adaptive: підключи `../../design-system/index.css` (єдину публічну точку входу) і
   `../../wireframes/wf-shell-responsive.css` / `.js`. У локальному CSS використовуй тільки
   наявні semantic color roles та primitive geometry/type/motion tokens із
   `design-system/tokens.css`. Mobile-first. На телефоні форма лінійна; від 67.5rem desktop
   може показати поруч контекст людини/майбутній відгук, не змінюючи сам job.
6. Motion: `DESIGN.md` §5 і `animations/motion-inventory.md`. Додай рух тільки як відповідь,
   статус або зв'язок станів; анімуй тільки `transform`/`opacity`, використовуй
   `--dur-*`, `--ease-*`, `--move-*`. `prefers-reduced-motion: reduce` має прибирати motion,
   не приховуючи кінцевий стан.

Зроби один основний екран форми відгуку та необхідні `loading`, `success`, `error`, `empty`
стани як окремі доступні HTML-сторінки зі спільними локальними CSS/JS. Форма містить лише те,
що підтверджено джерелами: людину/контекст спільного проживання та текст відгуку. Не додавай
зірок, числового рейтингу, тегів чеснот або критеріїв, яких немає в sitemap/JTBD. Текст відгуку
обов'язковий; не вигадуй max length. На submit покажи loading і заблокуй повторну дію; error
має зберігати введений текст і давати retry; success — чітко підтверджувати новий стан; empty —
пояснювати відсутність підтверджених проживань і вести до чатів. Додай позапродуктову компактну
навігацію між станами, явно позначену як навігація прикладу.

Забезпеч semantic HTML, зв'язані label/input, `aria-live` для async/result state, видимий
keyboard focus, touch targets не менше наявного системного патерна, коректні disabled/
`aria-disabled`, без залежності стану лише від кольору або руху. Не використовуй Playwright чи
screenshots.

Після реалізації виконай доступні статичні перевірки HTML/CSS/JS, перевір локальні посилання,
заборонені сирі кольори й layout-анімації, потім `git diff --check`. У фіналі назви створені
файли й чесно переліч припущення/обмеження RJ5.
```
